# LabscriptAI 用户视角评审

2026-10-23；基于 KRATSZ/LabScript-AI 的 main `72f1f6c`。本轮对象是当前聊天式网页，不是旧 LabscriptAI_cloud 的多页表单。用户明确保留旧项目文件，网页不提供或要求本地配置。

## 采用什么方法

浏览器自动化负责执行操作。用户视角评审另外回答：目标用户能否发现正确入口、理解动作、知道当前进展、从失败中恢复。

传统产品团队常用的组合：

| 方法 | 做法 | 能得出的结论 |
| --- | --- | --- |
| 认知走查 | 固定用户背景与真实任务，逐步检查目标、可见操作、含义、反馈 | 找出可能阻断首次使用的界面问题；属于专家判断 |
| 启发式评审 | 检查状态反馈、用词一致、控制权、错误恢复与信息负担 | 找到具体违反可用性原则的位置；不能替代真人行为 |
| 真人任务测试 | 让目标用户独立完成任务，不教点击路线，观察停顿、错误、求助与结果 | 了解实际使用障碍；小样本适合发现问题，不用于推断总体成功率 |
| 上线后观察 | 看任务漏斗、失败与放弃位置，再访谈原因；流量和问题稳定后再考虑 A/B | 判断真实使用中的频率与改动效果；本轮没有添加埋点或进行 A/B |

新找到的更相关 skill：

- [wondelai/ux-heuristics](https://github.com/wondelai/skills/tree/main/ux-heuristics)：适合轻量的导航、表单、状态与恢复检查；带任务测试参考材料。其主观打分不应包装为实测成功率。
- [Intent/evaluate](https://github.com/ghaida/intent/tree/main/skills/evaluate)：认知走查、启发式评审和问题排序，较适合深入评审完整流程；配套体系较大。

本轮参考方法，未安装这些 skill，也没有把 AI 评审称为真人测试。

## 当前版本的观察与改动

| 观察 | 对使用的影响 | 改动 |
| --- | --- | --- |
| 示例填文字，却不选仪器；按钮保持不可用 | 想先试用的人还需猜缺了什么 | 示例默认选 Flex，保留用户明确选择的其他仪器；不自动提交 |
| Notes 标签不能明确表达 SOP/已有代码入口 | 用户可能不知道现有材料放哪里 | 直接显示 SOP/代码粘贴框和可聚焦的上传入口，提示文件格式 |
| 首屏缺少产物与下一步的说明，按钮仅写 Let's go | 不能清楚预期接下来发生什么 | 说明核对方案、生成检查、预演下载；主按钮使用具体动作名称 |
| 服务缺密钥时直接显示内部配置问题，失败返回原始 JSON/HTML | 网页用户无法解决，也不知道如何继续 | 用简短中英文提示区分网络、服务忙、输入和会话过期；保留可用的实验诊断 |
| 首次加载包含整个官方台面播放器 | 即使只想填写实验也要加载大量代码 | 仅需播放器时加载；构建入口 JS 约 35,226 KB → 344 KB，播放器仍是约 34,879 KB 独立包 |
| 初版改动让提交按钮落在视口下方，随后固定操作区又挤小输入框 | 必须滚动找按钮，或输入内容被裁切 | 表单内容独立滚动、操作区固定可见，字段禁止被 flex 压缩；已查看真实截图 |

当前网站本身未发现旧的本地配置页，因此没有虚构“删除一个现存配置入口”。移除了首页面向用户的密钥配置提示；开发者运行文档与旧项目保留。

本轮另修：聊天输入框提供可访问名称；3D服务不可用不再让网页用户运行npm命令；独立部署的3D fallback不再显示8010和底层命令列表，并收起460px空白区，让真实预演画面可用。已实际点击吸液/分液步骤并核对时间跳转。三维标签明确为当前80 µL会话脚本，没有拿预置示例冒充用户协议。

修改流程增加服务端约束：非空跟进先内部同步完整当前目标，生成/检查/播放工具在同步前不能复用旧结果；目标变化后失效SOP、代码、Plan、analyze、下载产物与旧检查。初次确认与已有SOP也遵循相同流程。明确修改无需再让用户确认一次。草稿仅供生成时保留未变条件，reviewer只对照当前目标和新SOP。独立新上下文Codex发现的状态、换机、旧稿与reviewer问题均已修复并补回归。

### 尚未解决，发布前优先处理

1. **P1：确定性的实验约束不完整。** 当前绿灯不能代表移液精度合格。PCR的2 µL被1000 µL移液器接受，官方规格为5–1000 µL；应以官方仪器/枪头量程加独立校验，并在需要换硬件时让用户确认，不能擅改实验体积或假定用户已经换了移液器。[官方移液器规格](https://docs.opentrons.com/flex/system-description/pipettes/)、[官方API量程与体积模式](https://docs.opentrons.com/python-api/pipettes/volume-modes/)。
2. **P1：失败建议仍需要结构化约束。** 已去掉确定性错误文案里“分次修复同孔溢出”的建议，并加强模型规则；但真实回复曾把“换更大枪头”单独列为修复孔容量不足的办法。应从明确的tip/well容量问题生成可选方案，要求每项方案同时满足所有限制，不能只靠prompt声称修好了。
3. **P2：导入SOP的条件保真仍需完善。** 上传回测中，明确的源孔初始100 µL被SOP泛化成“足够80 µL”；reviewer未报此差异。应核对初始量、来源、混匀和换枪头条件等保留字段，不能只对照转移量判断导入成功。
4. 生成等待在本轮任务约20–85秒，修改任务可能需要一次自动修补；这不是延迟统计。后续真人观察应记录等待时的放弃、信任和求助，再决定更细的进度反馈。

本轮测试证明“能完成这几个合成任务”的范围，不能替代真人可用性、实机校准、试剂兼容性或全部协议正确性。PR继续保持草稿，不发布。

证据：[80 µL台面与对话](ux-review/flex-80-retest.png)、[同一80 µL协议的三维画面](ux-review/flex-80-3d.png)。原始合成任务快照、下载代码、工具轨迹与脱敏服务日志仅保留于本机`.local/live-qa-20261023/`，不把大批中间结果提交到项目。

最终验证：双 TypeScript、297 项 Node、46 项 Python 全部通过，生产构建通过；补充修改后86项针对性回归通过。独立新上下文Codex复审确认本轮修改流程无剩余阻断；以上两项产品级P1及SOP保真P2仍未解决，不能将代码复审通过解释为实验可靠性验收。

## 下一轮真人任务测试

先招募约 5 名相同目标人群的研究者或学生：懂移液实验，未用过这个网站，不要求会机器人编程。每人单独测试，以发现问题为目的；有经验的自动化工程师另作为不同人群观察。

给用户的任务只描述目的，不给按钮名或点击路线：

1. 你想用 Flex 将 96 孔板 A1 的 50 µL 水转移到 B1。请准备这份实验协议，并判断还有什么需要核对。
2. 你已有一份实验 SOP。请用网站把它变成可供仪器使用的协议。
3. 你发现体积应为 80 µL。请修改方案，确认代码、预演和下载文件属于修改后的版本。

观察并记录每人是否独立完成、哪里停顿、错在哪里、何时求助、如何恢复、最后产物是否符合目标。任务结束再问哪里最不确定。不要在测试中解释正确路线，也不要把几个人的结果宣传为整体用户成功率。第三个任务已通过本轮真实模型链路预验，可以用于后续真人测试。

优先修复阻断任务和误导结果的问题，用另一批目标用户重测；把能稳定复现的问题加入自动化回归。
