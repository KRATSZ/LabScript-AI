2Laboratory automation accelerates experimental throughput and reproducibility but robotic programming remains a bottleneck requiring extensive expertise. Here we introduce LabscriptAI, a multi-agent framework that autonomously generates and validates executable Python scripts for synthetic biology automation from natural language descriptions. On a 55-task benchmark, LabscriptAI achieved 89.1% success, substantially outperformed direct large language model implementation (20-45%) and a commercial LLM‑based solution (76.3%). LabscriptAI automated cell-free synthesis and characterization of 298 green fluorescent protein variants designed by 53 student teams; the top variant, with only five mutations, matched the brightness of superfolder GFP (an extensively optimized benchmark with 11 mutations). LabscriptAI also orchestrated distributed automation across a biofoundry and fume hood-enclosed systems to engineer enzyme variants that utilize hazardous formaldehyde, achieving a 7-fold increase in catalytic efficiency while improving personnel protection. Furthermore, LabscriptAI prepared 531 quality‑assured genetic parts for dissemination to 500 iGEM teams worldwide, integrating whole‑plasmid sequencing and biosecurity screening. By eliminating programming barriers, LabscriptAI democratizes synthetic biology automation while embedding responsible research, including biosecurity screening, physical containment, and human-in-the-loop oversight, directly into the automated workflow.IntroductionLaboratory automation is transforming experimental biology by enhancing throughput, reproducibility, and standardization, particularly in synthetic biology1-4. While advanced biofoundries provide centralized high-throughput robotics for large-scale projects, accessible platforms such as Opentrons have democratized automation through cost-effective and open-source design5, with community projects like AssemblyTron demonstrating DNA assembly automation6. Despite these advances, scripting liquid-handling robots remains a persistent bottleneck7,8. Protocol generation and adaptation demand substantial programming expertise, compounded by platform heterogeneity across Opentrons, Tecan, Hamilton, and other systems, each with distinct programming interfaces.Large language models (LLMs) present opportunities to bridge this accessibility gap, albeit with limited success. Inagaki and colleagues demonstrated that GPT-4 could generate functional OT-2 scripts from natural language instructions using simulator feedback9; however, this approach struggled with complex protocols, occasionally circumventing programming errors rather than implementing correct experimental steps. Hardware-agnostic interfaces like PyLabRobot10 have simplified multi-platform control, yet early integration with GPT-3.5 remains 
3restricted to basic user cases. Coscientist11 and ChemCrow12 demonstrated large language model–driven autonomous chemical experimentation but were confined to non-biological tasks. Reliable application of large language models to synthetic biology automation faces several fundamental challenges: general-purpose large language models lack domain-specific knowledge of biological protocols, reagent handling, and safety constraints; they struggle with managing hardware-specific variations in pipetting configurations, timing dependencies, and deck layouts; and they lack structured script validation mechanisms for iterative generation and debugging. Furthermore, reproducible protocols demand bidirectional integration with established databases and standards, a capability that is absent from existing large language model–based systems. These limitations, combined with biosafety and biosecurity concerns13,14, prevent deployment of large language model–generated scripts in real-world applications, where accuracy, reproducibility, and accountability are essential.Here we present LabscriptAI (Figure 1, https://labscriptai.cn/), a multi-agent framework that translates natural language descriptions of biological experiments into validated robotic code across heterogeneous liquid-handling platforms while enforcing domain-specific and safety constraints. Building on CodeAct15, LLM agents iteratively produce executable Python code and analyze execution outcomes to refine protocols rather than generating static scripts. When errors occur, the Precise Refactoring Engine generates targeted corrections instead of regenerating entire scripts, achieving faster convergence on validated protocols. LabscriptAI integrates a dynamic knowledge base that stores validated protocols, hardware specifications, and controlled terminology. Human-in-the-loop oversight maintains alignment between natural language procedures and Python scripts through synchronized updates. We validate LabscriptAI across experiments of increasing complexity, including cross-platform plate reader calibration, cell-free expression and characterization of green fluorescent protein (GFP) variants from a protein design competition, enzyme engineering involving hazardous reagents, and preparation of the 2025 iGEM Distribution Kit for community-scale genetic parts dissemination, demonstrating that accessible natural language interfaces can support responsible laboratory automation.ResultsSystem ArchitectureLabscriptAI comprises three integrated components (Figure 1): a web-based user interface, a code-generation and self-correction backend, and a storage layer containing both a long-term knowledge base and dynamic project-specific data. Together, these components translate high-level descriptions of biological experiments into executable automation code (Supplementary Note 1). The multi-agent system architecture is orchestrated using LangGraph16, with the 
4detailed prompt-engineering strategy provided in Supplementary Note 2.The web interface enables experimental goal specification for biological workflows through natural language input and hardware configuration (Extended Data Fig. 1). Real-time visualization displays dynamic generation and modification of both standard operating procedures in natural language and executable Python scripts, allowing researchers to monitor the transformation from high-level biological concepts to liquid-handling instructions (Supplementary Note 1). The system also accepts pre-existing standard operating procedures and robotic scripts, supporting both protocol adaptation and code refinement workflows (Extended Data Fig. 1).The Task Planning Agent coordinates workflow processing (Figure 1), initiating a human-in-the-loop dialogue to first validate and refine natural language SOPs. Once finalized, the agent determines the appropriate code generation strategy: adaptation of existing scripts for new hardware or user requirements, or de novo code generation. This hierarchical processing ensures accurate translation of experimental goals before code generation.The Code Graph backend manages iterative code refinement through a multi-stage pipeline (Figure 1). Initial Python script generation leverages the knowledge base resources and incorporates project-specific context. Generated scripts undergo validation using platform-appropriate simulators selected based on provided hardware configurations. Successful simulations yield deployment-ready code, while validation failures activate the code-modification pipeline. The Precise Refactoring Engine analyzes error messages and generates targeted SEARCH/REPLACE operations (Extended Data Fig. 2), preserving validated code segments rather than regenerating entire scripts. This iterative cycle continues until validation succeeds or retry limits are reached.The storage architecture separates persistent domain knowledge from dynamic project data (Figure 1). The knowledge base maintains validated biological protocols, hardware specifications, application programming interface (API) definitions, and controlled terminology, while workspace storage manages session-specific data, including simulation results and generation logs. Successful validations are promoted from workspace to knowledge base, creating a continuous-learning mechanism that improves system performance over time.These architectural components provide three key advances: adaptive task planning responsive to varying input scenarios, efficient code refinement through precise patches, and continuous learning through systematic feedback integration. System transparency, from detailed iteration logs to real-time visualization, facilitates interactive debugging and user understanding, enabling researchers without programming expertise to generate robust automation protocols while ensuring accuracy through multi-stage validation.
5Benchmark PerformanceTo evaluate the ability of large language models to generate liquid-handling scripts, we developed a benchmark (Supplementary Dataset 1) adapted and expanded from Inagaki et al.6 to comprise 55 tasks stratified across four difficulty levels: Easy (n = 13, basic liquid handling), Medium (n = 20, multi-step workflows), Hard (n = 13, complex error-prone operations), and Expert (n = 9, multi-module coordination). Performance was compared against direct LLM implementations (GPT-5, Claude 4, DeepSeek V3.2, Gemini-2.5 Pro) and OpentronsAI, a commercial LLM–based solution (Table 1).LabscriptAI achieved 89.1% overall success in generating simulation-passing scripts, outperforming all baselines (Table 1). Direct LLM implementations achieved 20–45% success, with performance degrading sharply at higher difficulty levels (zero success on Expert-level tasks for GPT-5 and Claude 4). Utilizing domain-specific fine-tuning, OpentronsAI reached 76.3% overall success, 12.8% below our open-source platform. LabscriptAI achieved 100% success on Easy and Medium tasks and maintained 76.9% and 66.7% success on Hard and Expert tasks, respectively, demonstrating robustness across complexity levels.Ablation studies quantified the contribution of individual architectural components (Table 2). Replacing the Precise Refactoring Engine with full-script regeneration decreased success to 80.0% while increasing average iterations from 3.07 to 4.38 and token consumption by 40%, demonstrating the efficiency benefits of targeted corrections. Removing domain-specific knowledge retrieval reduced success to 76.3% (12.8% reduction). Disabling iterative refinement reduced success to 18.2% (70.9% reduction), falling below direct LLM implementations (Table 1) despite access to domain knowledge. This dramatic degradation likely resulted from context overload: the combination of extensive knowledge retrieval and detailed agent prompts increased susceptibility to hardware constraint violations and API version mismatches during initial code generation.Error-pattern analysis revealed distinct failure modes (Extended Data Fig. 3). Direct LLM implementations exhibited hardware-constraint violations, API syntax errors, and hallucinated hardware capabilities. OpentronsAI showed improved API compliance but encountered logical errors in complex pipetting sequences. LabscriptAI failures involved edge cases in deck configuration and multi-dispense logic, representing refinement opportunities rather than architectural limitations.During benchmark evaluation, LLM occasionally refused to generate protocols and scripts for certain workflows, citing biosafety and biosecurity concerns (Table 1). These refusals underscore the importance of balancing risk mitigation with legitimate use of large language models in scientific automation. LabscriptAI implements a multi-layered safety framework to prevent inappropriate refusals: (1) protocol generation with explicit human oversight and approval, (2) biosecurity 
6screening for DNA synthesis, (3) physical containment for hazardous workflows, and (4) procedural safety instructions for research personnel. These safety-guardrail approaches (Figure 1) enable responsible robotic code generation and execution without sacrificing access to high-risk, high-value experiments.Cross-platform Validation of Community Plate Reader Calibration ProtocolFor experimental validation of cross-platform compatibility of LabscriptAI-generated scripts, the iGEM Plate Reader Fluorescence Calibration protocol17 was selected as a proof-of-concept challenge. This community standard, hosted on the protocols.io repository, enables conversion of arbitrary fluorescence units to standardized fluorescein equivalents for reproducible comparison across laboratories17. A collaboration agent was implemented (Extended Data Fig. 4), interfacing with protocols.io to retrieve the latest protocol version and deposit generated scripts via API. The natural language input to LabscriptAI consisted of the request "Prepare a fluorescein standard curve following the iGEM protocol" (Figure 2A). The Task Planning Agent generated a structured procedure comprising 10 μM fluorescein stock preparation, serial 2-fold dilutions across 7 concentrations, and triplicate plating in 96-well black plates with 200 μL final volumes (Figure 2B).Platform-specific scripts were generated for four liquid-handling systems (Figure 2C): Opentrons OT-2 and Flex (native Python API18, Supplementary Fig. 1), Hamilton Vantage (PyLabRobot10), and Tecan Fluent. For Tecan compatibility, pyFluent was developed in this study to provide a standardized Python API (Extended Data Fig. 5). The Precise Refactoring Engine generated targeted modifications for hardware-specific constraints, including pipette tip compatibility, deck layout differences, and liquid-handling protocols. Experimental validation produced coefficients of variation below 5% for triplicates, with linear regression R² values of standard curves exceeding 0.999 across all systems (Figure 2C). These results demonstrate LabscriptAI's capability to translate natural language protocols into executable, platform-optimized scripts.Robotic Screening of GFP Variants for Student CompetitionTo validate LabscriptAI in a biological context, a cell-free protein synthesis (CFPS) workflow was automated to express GFP using the pET28 vector on Opentrons Flex (Figure 3A), enabling rapid, transformation-free fluorescence profiling. The natural language input "Set up cell-free GFP expression reactions with varying template concentrations" was coupled with the commercial kit protocol, generating automated scripts for master mix preparation, template dilution series, and 37°C incubation (Figure 3B, Supplementary Fig. 2). The parent avGFP from the jellyfish Aequorea victoria19 (Supplementary Table 1) demonstrated robust and reproducible expression: CFPS reactions in 25 μL volume yielded strong fluorescence signals across template concentrations from 
70.25-7.50 ng μL -1, with 5.0 ng μL -1 producing 0.130 ± 0.001 μM fluorescein equivalents after 3-hour incubation (Figure 3C).LabscriptAI was subsequently applied to the Critical Assessment of Protein Engineering (CAPE) competition20. Modeled after the Critical Assessment of Structure Prediction (CASP) competition for protein structure prediction21, student teams develop computational models, submit designs for centralized characterization, and receive standardized performance data (Figure 3D). This framework promotes protein engineering by providing experimental feedback on cloud labs22 for model benchmarking and refinement. The 2025 CAPE challenge focused on engineering GFP variants with enhanced fluorescence (Figure 3D): Teams received 147,950 sequence-function data points from previous studies23,24 for model training, then submitted six designs each containing up to six mutations in avGFP, resulting in 298 dereplicated sequences from 53 participating teams across five countries. When compared with avGFP variants in FPbase25, a community-curated database cataloging photophysical properties of over 800 fluorescent proteins, student designs explored distinct sequence space (Figure 3E). Design strategies ranged from structure-guided methods to multi-stage screening (Extended Data Fig. 6A), and were implemented using diverse machine learning frameworks with prevalent transformer-based architectures including ESM26 and Saprot27 (Extended Data Fig. 6B). All submitted designs, computational strategies, and trained models were made openly accessible to promote community learning and method development.For experimental validation, all sequences underwent biosecurity screening using the open-source IBBIS Common Mechanism28 prior to synthesis (Figure 3D), ensuring submitted variants posed no dual-use concerns while supporting open collaboration. To accommodate competition scale, LabscriptAI adapted the CFPS protocols for multiple plates, optimizing master mix volumes and scheduling sequential measurements (Supplementary Fig. 2). GFP variants were characterized under standardized conditions, with fluorescence values normalized against batch-specific fluorescein calibration curves. Among 298 characterized variants, 53 demonstrated improved fluorescence values relative to avGFP under CFPS conditions (Supplementary Table 2). Single and double mutants showed limited improvements, while improved variant proportions increased substantially at three or more mutations (Figure 3F, Supplementary Table 2). This distribution pattern suggested that multiple coordinated mutations were required for substantial fluorescence enhancement, necessitating algorithm-assisted exploration of expansive sequence space. The top-performing variant Var1, containing five mutations (Supplementary Table 1) and exhibiting 8.11-fold improvement over avGFP in CFPS reactions (Figure 3F), was designed by multi-model ensemble predictions from six independent models with hierarchical filtering to converge on final candidates (Extended Data Fig. 6C). This provided a biologically meaningful 
8demonstration that community-designed sequences can yield substantially enhanced fluorescent proteins suitable for further biophysical characterization.Benchmark Community-Designed GFP Variants with Public DatabaseTo rigorously evaluate CAPE-winning variants, quantitative comparison was performed against FPbase benchmarks. While CFPS provides screening data, fluorescence measurement conflates expression level and molecular brightness29, so that protein purification is necessary for accurate photophysical assessment. LabscriptAI was therefore challenged with the request "Quantitatively compare CAPE GFP variants with FPbase bright GFP variants in purified form". The collaboration agent was extended to interface with FPbase (Extended Data Fig. 4), retrieving database entries via API and identifying superfolder GFP (sfGFP, Supplementary Table 1) as a high-performance benchmark variant of avGFP30. Metric specifications were extracted by the agent from the FPbase glossary and relevant literature31 and transmitted to LabscriptAI for protocol development.LabscriptAI first generated updated CFPS scripts with magnetic bead purification incorporating stepwise imidazole washes (Supplementary Fig. 2), Bradford assay for protein concentration normalization (Supplementary Fig. 3), and spectral collection for photophysical characterization. However, SDS-PAGE analysis revealed insufficient purity from microtiter cultures using bead-based purification (Extended Data Fig. 7A). Therefore, conventional two-step column chromatography was employed to manually purify selected variants from flask cultures (Extended Data Fig. 7B).The workflow concluded with automated data deposition back to FPbase through the collaboration agent (Extended Data Fig. 4). The system formatted characterization data according to FPbase standards, including excitation and emission spectra (Extended Data Fig. 7B), quantum yields, brightness, and extinction coefficients (Figure 3G). Measured values for avGFP and sfGFP differed numerically from those reported in FPbase, reflecting different assay conditions. Under our conditions, Var1 exhibited slightly higher quantum yield (0.80 vs 0.65) and molecular brightness (49.50 vs 41.33) than sfGFP, indicating that a community-designed variant can match or exceed the performance of an extensively optimized benchmark. Enzyme Variant Screening Involving Hazardous ReagentsTo extend LabscriptAI beyond fluorescent proteins, enzyme engineering workflows involving hazardous reagents were evaluated. This application targets one-carbon biomanufacturing using a glycolaldehyde synthase (GALS, Supplementary Table 1) from Pseudomonas putida, which catalyzes formaldehyde (FALD) condensation into glycolaldehyde (GALD) and dihydroxyacetone (DHA)32 (Figure 4A). Robotic automation mitigates researcher exposure to this carcinogenic chemical while 
9enabling high-throughput screening.Rapid spectrophotometric assays have previously been developed for product quantification of GALD and DHA from whole-cell biotransformation33. LabscriptAI was challenged with two key advances: first, distributing the workflow across the biofoundry (DNA and strain construction, Extended Data Fig. 8) and a fume hood-enclosed Opentrons OT-2 (FALD reaction and analysis, Figure 4B), connected by human-mediated transfers; and second, performing combinatorial mutagenesis at the V281 and F282 residues (Figure 4A), where single mutations had previously failed to yield improvements33. The natural language request was "Create combinatorial double-site mutagenesis library at V281 and F282, screen for enhanced FALD biotransformation activity using distributed automation".LabscriptAI orchestrated a multi-platform workflow (Figure 4B). The biofoundry workflow included: (1) automated library construction using Tecan Fluent with primers encoding 19 amino acid substitutions per position (38 single mutants and 361 double mutants); (2) clone picking and sequence verification; (3) automated cell cultivation, induction, and washing. Subsequently, induced cells were transferred to the fume hood-enclosed OT-2, and physically contained workflows included: (4) automated preparation of FALD-containing assay buffer (1.5 g L⁻¹ FALD in 50 mM PBS with cofactors); (5) static biotransformation at room temperature for 24 h; and (6) supernatant collection and splitting with separate derivatization for GALD and DHA quantification.LabscriptAI generated both robotic scripts and human operator instructions delineating safety-critical steps. FALD biotransformation (Supplementary Fig. 4) and product detection (Supplementary Figs. 5, 6) were confined to the fume hood-enclosed system, minimizing researcher exposure while maintaining throughput. For inter-station transfers, explicit safety instructions specified personal protective equipment, sealed plate handling procedures, and designated transfer routes (Supplementary Figs. 4-7). This approach demonstrates how strategic workflow partitioning enhances laboratory safety and automation efficiency.Automated screening for whole-cell FALD biotransformation (50 mM substrate, 24-hour incubation) identified several double mutants achieving improvements unattainable through single-site mutations (Figure 4C), validating the combinatorial mutagenesis strategy. Top variants were manually purified and evaluated for in vitro FALD conversion (66.7 mM substrate, 1 mg mL-1 enzyme, 2-hour incubation). Parent GALS yielded 5.3% conversion (1.52 mM GALD, 0.17 mM DHA), while W/L and W/T variants achieved 31.5% (8.39 mM GALD, 1.41 mM DHA) and 14.9% (3.30 mM GALD, 1.11 mM DHA) conversion, respectively (Figure 4D).LabscriptAI developed automated workflows for enzyme kinetics characterization (
10Supplementary Fig. 7). The W/L variant achieved 3.2-fold and 7.0-fold enhancement in catalytic efficiency kcat/Km for GALD and DHA, respectively, driven primarily by increased turnover (5.3-fold and 6.1-fold kcat) (Extended Data Fig. 9). Conversely, W/T variant improvements (2.2-fold and 3.1-fold catalytic efficiency) resulted from enhanced substrate binding (0.64-fold and 0.60-fold Km) with moderate turnover increases (1.4-fold and 1.8-fold) (Extended Data Fig. 9). The W/L variant also showed superior tolerance with little inhibition at 1,500 mM FALD (45 g L⁻¹), whereas parent GALS and W/T variant productivity decreased above 500 mM (15 g L⁻¹) (Figure 4E). This substrate tolerance is particularly notable given FALD's well-characterized protein-denaturing properties, representing a critical advance for industrial biocatalysis applications requiring high substrate concentrations.The collaboration agent processed enzyme data and metadata to address heterogeneous formatting requirements and access interfaces across repositories (Extended Data Fig. 4), ranging from programmatic API submissions in SABIO-RK34 to manual web form entries in STRENDA35, and from standardized XML-based SBML documents in EnzymeML36 to spreadsheet templates in BioCatNet37. The framework adapted experimental data to each database's metadata schemas, controlled vocabularies, and submission protocols, eliminating laborious manual reformatting and ensuring cross-laboratory standardization.Robotic Preparation and Quality Assurance for the 2025 iGEM Distribution KitThe preceding case studies validated LabscriptAI across diverse workflows of increasing complexity. To demonstrate that the framework could support broader synthetic biology operations, we applied LabscriptAI to automate preparation of the 2025 iGEM Distribution Kit, which delivers standardized genetic parts to hundreds of student teams worldwide for distributed experimentation. The Distribution Kit provides curated DNA collections encompassing promoters, reporters, plasmid backbones, and composite devices that serve as foundational resources for synthetic biology education and research. Because the kit involves global dissemination of recombinant DNA, responsible manufacturing requires both robust quality control and biosecurity oversight. Starting from dried plasmid DNA samples provided by collection maintainers and shipped to Shenzhen, the workflow began with bacterial transformation, clonal isolation, cell cultivation, and plasmid DNA isolation. These steps followed previously established biofoundry workflows on a Tecan Fluent station (Figure 5A, B; Extended Data Fig. 8). LabscriptAI generated Tecan Fluent scripts for downstream procedures, including plasmid DNA quantification, concentration normalization, and kit plate assembly (Figure 5B). Biosecurity oversight followed a layered framework (Figure 5C): at the curation stage, iGEM applied the Common 
11Mechanism to pre-screen all reference sequences for dual-use concerns; after robotic preparation, sequencing deviations from these pre-cleared references triggered additional biosecurity review. The 2025 Distribution Kit encompassed 584 genetic parts sourced, created, and curated by groups including the iGEM Engineering Committee, FreeGenes, Open Bioeconomy Lab, and Asimov. Eleven parts did not yield transformants despite repeated trials and were not further pursued. For quality assurance, whole-plasmid sequencing was performed on all 573 successfully transformed clones (Figure 5D). Of these, 171 produced perfect matches to expected reference sequences. Among non-matching clones, mutation analysis identified 346 with sequence deviations: 320 harbored a recurrent G-to-A substitution in the origin of replication present exclusively in plasmids carrying ampicillin-resistance genes, and 26 carried other mutations. These clones were included in the distribution with mismatches annotated. The remaining 56 were aligned against the full sequence collection across the kit; 42 produced no hits and were excluded, whereas 14 had been assigned to incorrect plate positions during upstream processing and were included after correction. At the biosecurity level, the 346 clones with identifiable mutations were assessed for altered risk profiles, as mutations from cloning errors or spontaneous mutagenesis could introduce unanticipated biological function. For the 42 clones producing no alignment hits to any reference, these most likely arose from sample contamination or degradation in this instance, yet the same framework would serve to detect erroneous or unauthorized sequence introductions in automated workflows.In total, 531 parts passed biosecurity screening and were assembled into the final kit. For kit assembly (Figure 5E), LabscriptAI integrated plasmid concentration measurements, whole-plasmid sequencing results, and plate inventory records together with Tecan Fluent hardware configurations as inputs, and generated executable scripts to dilute plasmid DNA with 0.1% Cresol Red in TE buffer to a normalized concentration of 2 ng μL-1 in 96-deep-well master plates. From these master plates, 3 μL aliquots were dispensed into two 384-well destination plates, air-dried, and foil-sealed to produce 500 distribution kits for shipment to registered iGEM teams worldwide. The system produced a comprehensive sample report detailing final plate positions, sequencing outcomes, and annotated mutations for each distributed part.DiscussionLaboratory automation is central to synthetic biology and protein engineering, where high-throughput, reproducible workflows are required to explore large sequence spaces and systematically optimize biological function1-4. 
12Liquid-handling stations, biofoundries, and distributed robotic platforms can scale experiments far beyond manual capacity, but this potential is constrained by the difficulty of translating complex experimental designs into robust code; scripting and maintaining automation protocols remain major bottlenecks, concentrating automation in groups with substantial engineering expertise and limiting broader community participation in large-scale, data-driven biology. Existing approaches only partially address this gap. LLM-based tools can generate scripts for specific platforms and tasks9-12, but often struggle with complex multi-step protocols, hardware heterogeneity, and reproducible debugging. Other autonomous protein engineering platforms38-41 focus on iterative sequence optimization guided by active learning algorithms, yet are typically tied to pre-defined protocols, fixed hardware configurations, and limited safety and data-integration support. Consequently, there is still no widely accessible framework that unifies cross-platform automation, robust error handling, built-in biosafety safeguards, and deep integration with community data resources.In this study, we introduced LabscriptAI, a multi-agent framework that integrates domain knowledge with iterative self-correction and provides natural language interfaces for programming-intensive laboratory automation. Across a 55-task benchmark stratified by difficulty, LabscriptAI achieved 89.1% success, outperforming direct LLM implementations (20–45%) and a commercial solution (76.3%). Experimental validation progressed through increasing biological and operational complexity. First, iGEM fluorescence calibration across multiple platforms demonstrated hardware-agnostic implementation. Second, characterization of 298 community-designed avGFP variants identified a leading candidate that, with five mutations (Supplementary Table 2), matched the strong fluorescence of sfGFP, which carries 11 mutations accumulated through extensive directed evolution30. Third, screening of FALD-utilizing enzyme variants yielded 7-fold enhanced catalytic efficiency and substantially improved tolerance from 500 mM to 1,500 mM substrate. Finally, automated preparation of the iGEM Distribution Kit assembled 531 biosecurity-screened genetic parts into 500 distribution kits with sequencing-based quality assurance. Notably, integration of LabscriptAI with the CAPE and iGEM competitions exemplifies democratized synthetic biology, enabling students to contribute diverse computational models, explore expansive sequence spaces, and access standardized genetic parts worldwide. These implementations confirmed that natural language interfaces can preserve automation precision and efficacy across diverse synthetic biology applications.Beyond empirical performance, LabscriptAI highlights general design principles for LLM-driven automation and its safe deployment. Three architectural features were particularly important for reliable code generation: hierarchical task decomposition, which separates high-level experimental logic from 
13platform-specific implementation so that biological procedures can be validated and refined before any code is produced; the Precise Refactoring Engine, which shows that targeted modifications are more effective than wholesale regeneration by preserving validated code segments and making debugging more interpretable; and knowledge retrieval from curated resources, which supplies domain expertise that generic LLMs lack, while separation of long-term knowledge from short-term project data enables continuous learning without compromising data integrity. In addition, structured prompts that emphasize biological intent rather than programming syntax further improved performance (Supplementary Note 2), underscoring that system architecture and interaction design must be co-optimized for robust and scalable automation. Complementing these architectural features, a multi-layered safety framework establishes a template for responsible use of such systems in the wet lab. Biosecurity screening of all community-submitted sequences before synthesis, including a student-accessible Google Colab implementation (Supplementary Fig. 8), embeds safety at the design stage. For community-scale parts distribution, a two-layer framework applied pre-curation sequence screening followed by post-production review triggered by sequencing deviations, ensuring biosecurity oversight throughout the production pipeline. Workflow partitioning confines hazardous operations, such as formaldehyde handling, to controlled environments, paired with automated execution of high-risk steps, explicit safety instructions for manual interventions, and human-in-the-loop oversight at critical decision points. Progressive validation from computational simulation through physical execution further reduces the likelihood that unsafe or erroneous protocols reach the bench. Together, these architectural and safety layers illustrate how LLM-based automation can be engineered to strengthen, rather than erode, existing biosafety and biosecurity norms.Bidirectional integration with community databases advanced reproducible synthetic biology research in line with FAIR (Findable, Accessible, Interoperable, and Reusable) principles42-45 (Extended Data Fig. 4). By retrieving protocols from open repositories such as protocols.io, adapting them to specific hardware, and depositing validated implementations, LabscriptAI contributed to a self-reinforcing cycle of shared methods and data. Automated reconciliation of heterogeneous database formats, via API calls, file format conversions, and structured data exports, reduced barriers to multi-database deposition that typically limit dissemination. More broadly, dynamic retrieval-augmented generation from curated community resources enabled accurate translation of biological requirements into robotic instructions, helping to establish collaborative ecosystems in which each successful protocol enhances future experimental and computational capabilities.Several limitations indicate development priorities. First, the current 
14implementation addresses individual liquid-handling robots; extending integration to additional processing, conditioning, and analytical devices would enable end-to-end automated workflows. Second, real-time decision-making based on intermediate results remains challenging, as the framework operates on pre-defined protocols rather than adaptive experimentation. Hardware-in-the-loop feedback systems could enable dynamic error detection and correction beyond pre-defined patterns. Third, incorporating experimental outcome data into the learning loop would facilitate protocol optimization based on historical performance metrics. Integration with electronic laboratory notebooks would provide comprehensive experimental tracking and enhance reproducibility documentation. Looking forward, the convergence of more capable language models, broader hardware integration, and expanding community knowledge bases suggests that natural language-guided automation will increasingly become standard practice in biological laboratories. We envisage extending LabscriptAI from liquid handling to full biofoundry orchestration, coupling it with adaptive experimentation engines that update protocols in response to interim measurements, and embedding it more deeply within FAIR-compliant data infrastructures. In parallel, open-source release of LabscriptAI with built-in biosafety and biosecurity safeguards will enable community-driven extension of its capabilities while maintaining responsible use, helping to democratize protein engineering and synthetic biology for the benefit of society.In conclusion, our results position LabscriptAI as both a practical tool for current laboratories and a conceptual blueprint for future LLM-driven automation. By coupling natural language interfaces with cross-platform code generation, multi-layered safety, and deep integration into community data ecosystems, LabscriptAI shows that automation can be made more accessible without compromising rigor or responsibility. As the underlying models, instruments, and datasets continue to evolve, we anticipate that similar frameworks will help transform laboratory practice from bespoke scripting to reproducible, shareable, and collaboratively optimized automated workflows.References1.Zhang, X.E. et al. 17MethodsSoftware FrameworkLabscriptAI was implemented as a multi-agent system orchestrated using LangGraph (v0.4.8)16. The web-based user interface (Extended Data Fig. 1, Supplementary Note 1) was developed using React (v18.3.1) and deployed at https://labscriptai.cn/. The system architecture (Figure 1) comprised a Task Planning Agent that coordinated workflow processing and initiated human-in-the-loop dialogue to validate natural language protocols. The Code Graph backend contained two primary agents: a Coder agent for generating Python scripts using platform-specific APIs, and a Reviewer agent for code validation using appropriate simulators. When validation errors were detected, the Reviewer passed error messages back to the Coder agent, which employed the Precise Refactoring Engine (Extended Data Fig. 2) to generate SEARCH and REPLACE instructions targeting specific error locations rather than regenerating entire scripts. The Reviewer agent executed these modifications and re-validated the updated code. This Coder-Reviewer interaction cycle continued iteratively, with a maximum limit of nine iterations per script generation request.Hardware platform-specific simulators were integrated for validation: opentrons_simulate (v8.5.1) for Opentrons systems, the PyHamilton module of PyLabRobot (v0.1.6) for Hamilton Vantage, and the newly developed pyFluent (Extended Data Fig. 5) for Tecan Fluent to provide a standardized Python interface compatible with the proprietary Tecan software environment.A Collaboration Agent interfaced with external databases and repositories (Extended Data Fig. 4). For protocols.io, the agent inter-converted between natural language SOPs and API-compatible JSON structures for versioned storage and retrieval. For protein databases, ad hoc Python code was implemented to accommodate heterogeneous access methods, formatting requirements, metadata schemas, and submission protocols, enabling automated deposition in compliance with platform-specific requirements and FAIR data principles.LLM Selection and Prompt EngineeringThe framework integrated Gemini 2.5 Pro through the OpenRouter API (v1.0) for all LLM operations.
